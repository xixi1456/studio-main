## 收尾验证（自动化审计抓出的三类真实缺陷）

用 Playwright 真实浏览器做视觉+可见性审计，抓到并修掉了三个静态截图看不出来的问题：

1. **`FadeIn` 滚动触发边距导致首屏内容不可见（最隐蔽）**
   `viewport.margin` 曾是 `0px 0px -200px`，负 bottom margin 把「进入视口」判定线上移，位于首屏底部/刚好压折叠线的元素会永远停在 `opacity:0`——必须多滚一点才出现。收窄到 `-120px`→`-40px` 仍会漏（项目详情页第一个拆解段落 top=898 / 视口 900，差 2px 就不触发）。
   **最终方案**：`const viewport = { once: true, margin: "0px" }`，只要有任意部分进入视口就触发，从根上杜绝；首屏元素另外用 `FadeIn` 的 `onMount`（`initial/animate` 而非 `whileInView`）双保险。`FadeInStagger` 同样支持 `onMount`。
   → **教训：负的 viewport margin 是「内容不显示」类 bug 的常见来源，宁可不用。**
2. **`Hero` 在 1366×768 上主 CTA 落到折叠线以下**（`ctaBottom=820 > 768`）
   pt 由 `sm:pt-36 lg:pt-40` 改 `sm:pt-32 lg:pt-[7.5rem]`，h1 由 `clamp(2.6rem,8.4vw,6.5rem)` 改 `clamp(2.6rem,8vw,6rem)`，内容区 `mt-12 lg:mt-16` 改 `mt-10 lg:mt-12`。复测 1366/1440/1536/1920 四档 CTA 全部在首屏内（h1=96px）。
3. **文案重复 / 数据层被绕过**
   `/join` 的 PageIntro 引言与「招新方向」段落都是 `recruitment.lead`，同时「没有基础也可以」卡片的正文被硬编码，绕过了 `openness.desc`。已拆成 `lead` / `directionsLead` / `openness.lead`（`desc` 保留给 metadata），页面全部改回读数据。
4. 顺带：移动端全屏菜单 `bg-ink/95 backdrop-blur-xl` 会透出底层页面文字，改纯 `bg-ink`；二维码占位 SVG 原是深色底但外层卡片是白底（真实二维码需要浅底才能扫），改成浅色版。

### 踩到的两个坑（可复用）

1. **外层透明度的坑**：水印容器写 `text-white/[0.07]`，但内部三角写 `className="fill-accent"` —— `fill-accent` 是**不透明主色**，不受外层 text 透明度影响，于是渲染出一个巨大橙色三角。水印里的主色元素必须单独给 `fill="#FF4D2E" fillOpacity="0.1"`。
2. **viewBox 留白实测**：机器人 PNG 是 440×440 且几乎占满画布（实测 alpha bbox 在 400 viewBox 里是 x 18–381 / y 38–361），所以标签文字**只能放在上沿左右空白区**。原来按 `left-0/right-0` 放，文字直接压在机器人身上不可读、且超出 viewBox 被裁。
   → 正确做法：**先用 canvas 量出图片的 alpha bbox**，再把标注放进真正空白的区域；标签改成两行（中文 + 英文），圆点落在机器人部件上、引线向外。
   → 量 bbox 的脚本思路：`drawImage` 到 canvas → `getImageData` → 扫 alpha > 12 的最小/最大 x,y → 按 `object-contain` 换算到 viewBox 坐标。
